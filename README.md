# video-engine

Hybrid vertical-video engine. Input: one project directory with `master_timeline.json`. Output: `<project>/out/final.mp4` (H.264 1080x1920, AAC 48 kHz) and `<project>/out/build_report.json`, published only by a build in which every gate passes; a failed build leaves both unchanged and writes `<project>/out/build_report.failed.json`.

Specification: [docs/SPEC.md](docs/SPEC.md). Rust crate: [docs/RUST.md](docs/RUST.md). Sound sourcing: [docs/SOUND.md](docs/SOUND.md). Design reasons: [docs/RATIONALE.md](docs/RATIONALE.md).

## CLI

All commands take the project directory. Exit code 0 = success, 1 = gate failure or engine error, 2 = usage error, 3 = waiting for an agent response (agent provider wrote a request bundle).

AI options (`draft`, `director`, `preflight --ai-qa`, `build --ai-qa`): `--provider NAME` (`gemini`, `agent` or a `[providers.NAME]` entry), `--resume` (agent provider: read the pending bundle's `response.json`).

| Command | Effect |
|---|---|
| `engine validate P` | Schema check only. |
| `engine preflight P [--captions] [--no-dom] [--ai-qa [--provider NAME] [--resume]] [--write-fixes]` | All pre-flight gates without rendering. `--captions` transcribes the voiceover for caption gates. `--write-fixes` writes auto-fixes (camera intensity, caption y overrides) back into the timeline. |
| `engine build P [--no-cache] [--relock] [--label L] [--timing-tsv F] [--ai-qa [--provider NAME]] [--resume] [--keep-workdir]` | Full build. Alias: `engine render`. Exit 0 when the build published `out/final.mp4`; exit 1 on any gate fail or stage error (nothing published, `out/build_report.failed.json` written). Missing music or SFX of a profile `[sound]` (docs/SOUND.md): writes `P/out/sound_request/` and exits 3; `--resume` (no `--ai-qa` needed) imports the agent's `response.json` and continues the build. `--no-cache` deletes the files of the cache entry directories (`words/`, `segments/`, `maps/`, `models/`, `dom/`) first, except files leased by a running build (printed as `cache: kept N files leased by a running build`); the build repopulates them. When the build's cache evictions deleted or skipped files, the command prints `cache: evicted N, skipped M leased` with one `skipped (leased): <path>` line per skipped file and the reclaimed stale leases. Other directories under the cache root are kept. `--timing-tsv` appends per-stage wall times. `--relock` drops the sound lock of `out/build_manifest.json` and resolves music and SFX again (see Build manifest). |
| `engine preview P --seg N --time S [--out F]` | One PNG of segment N at S seconds from segment start, no segment render. |
| `engine audio P [--no-cache]` | Prints caption words with frame ranges. Writes nothing. |
| `engine words P [--retranscribe] [--print]` | Transcribes the voiceover (words cache unless `--retranscribe`), applies `caption_fixes`, writes `captions` + `captions_meta` into `master_timeline.json` (atomic replace). Run after changing the voiceover, `caption_fixes`, `whisper_model`, `language`, `initial_prompt` or `fps` (gate W01 names the change). |
| `engine deliver P --dry-run [--final F]` | Prints the delivery plan as JSON. `--dry-run` is required; no upload exists. |
| `engine draft P [--out F] [--force] [--max-repairs 0-2] [--no-director] [--review [--review-rounds 1-2]] [--video-proxies N] [--voiceover F] [--script F] [--no-dom] [--provider NAME] [--resume]` | The AI provider drafts a timeline (see Draft). Writes `master_timeline.draft.json` (or `.rejected.json` when gates still fail after the repair rounds) and `draft_report.json`. Never overwrites `master_timeline.json` unless `--out` points there and `--force` is given. `--no-director` skips the storyboard stage; `--review` adds the review pass (see Director stage). |
| `engine director SRC [--start S] [--seconds N] [--provider NAME] [--resume] [--bundle-root D]` | Footage analysis of a 360p 5 fps proxy by the AI provider. Prints `provider`, `model`, `tried`, `usage`, `data` as JSON. Agent bundles go under `--bundle-root` (default `/dev/shm/video_engine/ai_request`). |
| `engine pauses P [--threshold-db D] [--min-pause S] [--min-seg S] [--max-seg S] [--json]` | Narration pauses (Rust energy detector on 16 kHz mono PCM) as half-open frame ranges, plus suggested segment boundaries at pause midpoints with segment lengths in `[min-seg, max-seg]` seconds (defaults 0.2 / 2.0 / 6.0). |
| `engine doctor [--install]` | Checks the pinned toolchain in `vendor/`; exit 1 when a component is missing or mismatched. `--install` downloads and installs only the failing components. |
| `engine clean [P ...] [--cache]` | Deletes the scratch root, `P/ai_request/` of every given project, and with `--cache` the files of the cache entry directories `words/`, `segments/`, `maps/`, `models/`, `dom/`, except leased ones (one `kept (leased by a running build): <path>` line each). |
| `engine cache --prune [--project P ...] [--dry-run]` | Deletes `words/`, `segments/`, `maps/`, `models/`, `dom/` entries of the cache that are not referenced by the current keys of the projects (segment renders and, when the render is cached, its graded file; map derivatives and deep tiles; model prop sprites; DOM probe results of the current HyperFrames segment keys) (default: every `examples/*/` project with a `master_timeline.json`). Also deletes broken sound cache entries (`video_engine.sound.cache.prune`; reported as `sound/...`, rewritten index files in `sound_rewritten`). Other directories under the cache root are not touched. Files leased by a running build are kept and listed in `skipped_leased`; lease files of dead processes are deleted and listed in `reclaimed_leases`. A project that fails to load stops the prune (exit 1, nothing deleted). |
| `engine import-shots CSV DST --search DIR [--search DIR ...] --credits F --voiceover F [--manifest F] [--substitute OLD=NEW ...] [--exclude SHOT ...] [--watermark-checked] [--project-number N] [--topic T] [--date D] [--force]` | Builds a project (`master_timeline.json`, `credits.txt`, `assets/`) from a shot-list CSV (`shot,type,file,title,source_url,author,licence,on_screen_s`) of an existing edit. Sources are only read. Credits come only from CSV or manifest rows; a row without `source_url` is an error. `--substitute` takes the new file's credit from the manifest (no row = error). `--exclude` merges a shot into the previous one. Map rows become `map_pins` HyperFrames segments with empty pins (add pins before building); stills alternate zoom in/out. Refuses an existing timeline without `--force`. |
| `engine taste CHANNEL [--like WHAT --why WHY \| --reject WHAT --why WHY]` | Prints the channel taste store (`profiles/taste/<channel>.json`, or `$VIDEO_ENGINE_TASTE_DIR/<channel>.json`); `--like` / `--reject` appends an entry with its reason. |
| `engine sheet P [--video F] [--out F] [--cols N]` | Contact sheet `out/sheet.png`: one tile per segment (middle frame, 1/5 size), labelled `seg N HF|N mm:ss.f`. |

## Timeline rules

- `profile` (optional): channel profile name (`profiles/<profile>.toml`). Absent = `default`. An unknown name fails schema validation and lists the known profiles.
- `gates` (optional): `require` (style gate ids added to the channel's required set; a project can add, never remove) and `waive` (style gate ids whose findings become info; a waive of a required or technical gate is ignored with a GW01 warn).
- `hold: "read"` (optional, on a segment or a HyperFrames beat): the viewer reads there; P01 hold and N01 gap findings starting inside it become info unless the gate is required, and no camera pulse is placed on that beat's wait.
- Time unit is the integer frame. `start_frame` inclusive, `end_frame` exclusive. Seconds are converted with `round(s * fps)`.
- Segments are contiguous from frame 0 (gate T02).
- `engine_type`:
  - `NATIVE_RUST_FFMPEG`: exactly one of `source_image` / `source_video`. Stills require `camera_move`. Video without `camera_move` is stream-copied when its video stream has exactly the engine segment format (Stream-copy and concat rules) and a keyframe at `source_in_frame`, else re-encoded.
  - `HYPERFRAMES_GSAP`: `gsap_scene_config` with `map_asset`, `pins` (`label`, `x`, `y` in 0-1 of the map, `at_frame`, `label_side`), `cards` (`title`, `subtitle`, `position`), `camera_preset`, `camera_intensity`, `focus`, `camera_path`, `regions`, `routes`, `title`, `title_entity`, `title_at_frame`, `figures`.
  - `camera_path` (optional, replaces `camera_preset`): >= 2 keys `{at_frame, focus: [x, y] 0-1 of the map, zoom 1.0 up to profile `[camera] max_zoom`, move}`. Key 0 is at frame 0; `at_frame` strictly increases and stays below the segment length (T02). `move` = the move from the previous key: `glide` (eased travel over the whole leg), `settle` (see `beats`) or `whip` (the camera drifts on the previous view, then a fast `power3.inOut` move of profile `theme.whip_s` lands on the key, with directional motion blur peaking at `theme.whip_blur_px` mid-move and none on its first and last frame; a leg shorter than `whip_s` whips over its whole length). After the last key the camera drifts (push-in at a constant profile `theme.camera_drift_per_s` ln zoom per second about `[camera] pulse_anchor`) to the segment end. Optional key field `drift_max` (ln zoom 0.01-2) bounds the drift of the wait on that key's view: it turns between 0 and the bound. Beats scenes write it for each wait whose drift breaks a per-frame layout rule (0.7 of the offending offset, floor 0.03). Pulse legs keep the drift's ln rate at both ends; a whip starts and lands at rest. With profile `[camera]` `pulse_zoom` > 0 every drift (before a whip and after the last key) holds evenly spaced pulses: (drift length - `pulse_gap_s`) // (`pulse_s` + `pulse_gap_s`) pulses alternating away from the drift and back to it. Optional key field `pulse` (0-1, or a list with one size per away pulse, the last repeating) sets the pulse sizes of the wait on that key's view; 0 = drift only. Beats scenes write it: the layout planner shrinks (0.75, 0.5, 0.25, 0 of `pulse_zoom`) each away pulse whose frames break a per-frame layout rule or move a pin label. Whips and drifts are inside one segment, so they are never cuts (C01). Transforms are clamped so the map always covers the frame. Optional key field `tilt` (deg, 0-60, default 0): perspective tilt of the map plane at that view, reached with the key's move and ease; the map, regions, routes, pins and map props turn together about the frame centre under `perspective(frame height) rotateX(tilt)` (top recedes), screen texts and screen props stay flat. Beats scenes do not tilt.
  - Pins follow `theme.pin_style`. `dot`: a dot in `theme.pin_colour` with a pulse ring and a boxed label above. `teardrop`: a teardrop head in `theme.pin_colour` with a white centre dot drops in with a bounce onto its shadow (0.6 s); a white, shadowed label of `theme.pin_label_px` in `theme.label_font` (`inter` or `script` = Kaushan Script) sits beside the head on `label_side` (`right` when absent). Pin bodies and labels keep one on-screen size at every camera key. With `theme.text_outline_px` > 0 teardrop labels and titles get an outline of that width outside the glyph in `theme.text_outline_colour` at `text_outline_alpha` (stroke painted under the fill) and a drop shadow (`text_shadow_dy_px`, `text_shadow_blur_px`, black at `text_shadow_alpha`) in place of the plain dark shadow; CSS variables `--txt-outline-px`, `--txt-outline`, `--txt-shadow`.
  - Map pixels: the map is drawn from a derivative of at most 3000 px on its longest side. When a frame zooms past the derivative's density, the segment also carries deep tiles: 1024 px tiles (2 px overlap) of the source resampled to the width the deepest frame needs (at most the source width), only where such frames look (+5 % margin), cached in `maps/` and drawn over the derivative inside the map layer, so map filters and grades cover both.
  - `regions` (optional): entity highlights `{entity, polygon: [[x, y], ...] >= 3 points 0-1 of the map, at_frame (default 0), edge}` drawn on the map under the pins: fill in the entity colour at `theme.region_fill_opacity`, edge `white` (white line) or `glow` (line and glow in the entity colour at `theme.region_glow_alpha`, radius `region_glow_px`; below 1 the glow sits on a stroke-only copy so the fill keeps exactly its opacity; absent = `theme.region_edge`) of `theme.region_edge_px` on screen at every zoom; fade-in 0.5 s from `at_frame` (below the segment length, T02). A region counts as a graphic event for H01 and N01.
  - `routes` (optional): movement lines `{points: [[x, y], ...] >= 2 points 0-1 of the map, at_frame (default 0), draw_s}` drawn on the map under the pins: a dashed line in `theme.route_colour` (`route_width_px` wide, `route_dash_px` dashes, `route_gap_px` gaps on screen at every zoom) draws itself from the first to the last point over `draw_s` (absent = `theme.route_draw_s`) with an in-out ease, and an arrowhead of `theme.route_arrow_px` rides the drawing tip. The drawing must end inside the segment (T02). A route counts as a graphic event for H01 and N01.
  - `title` (optional): big title centred near the top (top edge at 11 % of the height, max 900 px wide, wraps) from `title_at_frame` (default 0) to the segment end, in the colour of `title_entity` (absent = white) mixed `theme.title_tint` (0-0.6) toward white, with a same-colour glow of `theme.title_glow_px`; `theme.title_px` in `theme.title_font` (`inter` = Inter Bold, `title` = Archivo Black); 0.5 s scale and fade in. `title_entity` without `title` = T02 fail.
  - `figures` (optional): big years and numbers `{kind: year|number, value, decimals (numbers, 0-3), prefix, suffix, motion: bounce|counter, count_from, count_s, at_frame, position: [x, y] 0-1 of the frame (centre, default [0.5, 0.3]), entity}` shown from `at_frame` to the segment end at `theme.figure_px` in the entity colour (absent = white) with a dark shadow. Years: Playfair Display weight 800, whole numbers 1-9999. Numbers: `theme.title_font`, thousands separator `theme.number_group`, decimal separator `theme.number_decimal`, rounded half up. `bounce`: elastic scale-in over 0.9 s. `counter`: counts from `count_from` to `value` over `count_s` (absent = `theme.counter_s`) with a cubic ease-out (GSAP `power2.out`). The entrance must end inside the segment (T02). Titles and figures count as graphic events for H01 and N01, and their text counts as screen text for K01.
  - `props` (optional; also per beat, timed from the beat start): free-positioned PNG or WebP images with alpha, or glTF / GLB / OBJ models rendered to one `{asset, asset_id, model {yaw (deg, default 30), pitch (deg above the horizon, -89 to 89, default 20), fov (0 = orthographic, else perspective degrees, default 0), size_px (sprite side, 64-2048, default 512), turntable_s (seconds per turn, looping; omitted = still), turn_deg (default 360)} (model assets only; defaults when omitted), anchor: map|screen, x, y (map: 0-1 of the map; screen: frame px) or lat, lng (map, via map_bounds), width_px or width_map (fraction of the map width), rotation (deg), opacity, t_in, t_out (frames, t_out exclusive, default segment or beat end), enter / exit {kind: fade|pop|slide, s, ease: glide|drift|whip, dir, distance_px (slide)}, idle {kind: bob|rotate, amplitude, period_s}, depth (0-2, map props: grows (s / s_in)^(1+depth) and parallaxes by 1+depth against the camera), z (stacking), shadow {dx, dy, blur, alpha}}`. Map props are positioned every frame from the shared camera legs (`window.__legs`) over the map; screen props sit over the shade under the texts. The segment key holds every prop image's bytes and parameters and `hf/props.js`. Model props: `video_engine/models.py` renders the model with three.js in the vendored headless Chrome (SwiftShader) to an RGBA PNG sprite, fitted by its bounding sphere and lit by a fixed hemisphere and key light; a turntable is min(240, round(turntable_s x fps)) frames composed into one sprite sheet (at most 8192 px wide). Sprites are cached (kind `models`) under the BLAKE3 of the model, every file it references, the render parameters, the renderer scripts and the toolchain identity.
  - `layers` (optional): parallax layers, repeating full-frame images over the map and the map props, under the shade and the texts `{asset (.png/.webp with alpha or .jpg, tiled), asset_id, depth (-0.9 to 2, default 0.5: 0 moves with the map, > 0 nearer and faster, < 0 farther and slower), tile_px (on-screen tile width at frame 0, default the image width), opacity, blend: normal|screen|multiply|overlay|soft-light, drift [vx, vy] (px/s at frame 0 scale)}`. Per frame, with k = (s / s0)^(1+depth): grid origin = frame centre - s0 k (1+depth) (c - c0) + k drift t, tile width = tile_px k (`video_engine/parallax.py`, rendered by `hf/parallax.js`). Tilted scenes tilt the layers too. The segment key holds every layer image's bytes.
  - `globe` (optional): Blue Marble globe instead of the flat map `{keys [{at_frame (first 0, increasing), lat (-85 to 85), lng, altitude (camera height over the surface in globe radii, 0.005-12), tilt (0-60 deg, view tipped from straight down toward local north)}], detail_tiles (project-relative dir of the NASA 8-tile set *.A1.jpg ... *.D2.jpg, 90 deg each)}`. `map_asset` is a whole-world 2:1 equirectangular image. A globe scene takes no camera_path, beats, regions, routes, props, layers or map_bounds; pins take lat/lng. three.js (vendor/npm) draws a unit sphere with the map downscaled to 8192 x 4096 (cache kind `maps`) at a 30 deg vertical field of view; keys are joined by `glide` legs (great-circle direction, log altitude, linear tilt) and the altitude drifts in at the profile drift rate after the last key. Frames needing more texels per degree than that texture get detail patches cut from the tiles (240 px/deg) or the map: one per density level and run of frames, at most 4096 px a side, drawn coarse to fine (`video_engine/globe.py`, rendered by `hf/globe.js`; pins are placed at their three.js projection and hidden on the far side). The segment key holds the texture and patch content keys.
  - `beats` (optional, profile `[layout]` only): `[{at_frame (relative to the segment start, strictly increasing, first 0), region, pins, markers, routes, title, card, area_labels: [{text, region}], camera}]` — what is on screen from each beat to the next. `pins` show head and label, `markers` the head only, `card` = `[year figure]` or `[year figure, time figure]` (Z1, not with `title`), `camera` false keeps the previous view. With beats the layout derives `camera_path`, every element `at_frame`, `title_at_frame` and all positions; hand-written values for them are replaced. `routes[].to_pin` (beats only): the route ends short of that pin's head. Camera key `move` `settle` = an eased `power3.inOut` move of `move_s` (default `theme.whip_s`) ending on the key, without blur. Rules: docs/SPEC.md, G.
  - Entity colours: one colour per entity for the whole video. `[theme.entities]` maps entity -> `#rrggbb`; every other entity takes the next unused `theme.palette` colour in order of first appearance (segment order; in a segment regions, title, figures). E01 checks the painted colours.
- `camera_move`: `preset` (`ken_burns_zoom_in`, `ken_burns_zoom_out`, `pan_left`, `pan_right`, `pan_up`, `pan_down`, `static`), `intensity`, `auto_intensity` (default true), `focus_box` `[x0, y0, x1, y1]` in source pixels.
- `grade` (optional, any segment; also per beat, from the beat to the next): full-frame colour grade `{lift, gamma, gain (one value or [r, g, b]; -0.5-0.5, 0.2-5, 0-4; defaults 0, 1, 1), saturation (0-3, default 1, Rec. 709 luma), tint {color #rrggbb, amount 0-1} (hue and chroma toward the colour at the same luminance, clipped), lut (project-relative 3D .cube, applied after the values above), strength (0-1, default 1: mix over the ungraded picture)}`, applied in that order. Per frame: the beat's grade, else the segment's, else profile `[grade]`; `{}` = no grade. The grade is baked into one 33-point 3D LUT and applied by ffmpeg `lut3d` (tetrahedral, BT.709 both ways) to the rendered segment file, per frame range, before transitions and captions (captions are not graded). Graded files are cached in `segments/` under the rendered file's hash, the baked LUTs, their ranges and the encoder settings; the segment's mode in `build_report.json` gains `+grade`.
- `visual_type` (optional, any segment): `map`, `photo`, `video`, `diagram`, `archive` or `illustration`. Absent = HyperFrames `map`, native still `photo`, native video `video`. Read by gate V01 and profile `[transitions]` `by_type`; not part of any cache key.
- `overlays` (native segments): `{id, box: [x, y, w, h] output px, kind, text, subtitle, start_frame, end_frame}`.
  - `kind`: `reserve` (default; not drawn, reserves space for caption placement), `label` (centred single title on a dark plate), `text_card` (title + optional subtitle, accent bar), `lower_third` (name + role, accent bar).
  - Drawn kinds need `text`. `start_frame` / `end_frame` are relative to the segment start (half-open; defaults: whole segment). Fade in/out 0.2 s (shortened to a third of a short range).
  - Rendering: Pillow draws an RGBA PNG exactly the box size (Inter Bold/SemiBold; text wrapped, font shrunk from 54/72/64 px down to 26 px at 1920 height until it fits); ffmpeg composites it in the same encode as the segment (`overlay` with `enable=between(n,a,b-1)`). A segment with drawn overlays is never stream-copied. Overlay spec, font hashes and the Pillow version are part of the segment cache key.
  - Previews (`engine preview`) and gate snapshots include the drawn overlays.
- Every visual source and the BGM need a `credits_manifest` entry (`asset_id`, `path`, `source_url`, `license`, `watermark_free`). `credits.txt` in the project must contain every source URL. Licence `Own` / `Generated` needs no URL.

## Captions

- Compiled to `.ass` by Rust (`compile_ass`). 1-2 words per event. No background box (BorderStyle 1). White bold Inter, outline 5, soft offset shadow layer. Default font size 84 at 1920 px height.
- `caption_style` keys passed to Rust: `slot` (`lower` 0.70H, `mid` 0.50H, `upper` 0.24H), `font`, `size`, `bold`, `outline`, `soft_shadow`, `max_words`, `max_chars`, `active_word_highlight`, `margin_x`, and the other keys of the Rust `Style`. Unknown keys fail gate L22.
- Effective style = profile `caption_style` with the project `caption_style` keys on top.
- Python-only keys: `auto_place` (default profile: true), `clearance` (px at 1920 height between a caption box and an element box; default profile: 160; 0 = must not intersect), `y_overrides` (`[[start_frame, end_frame, y_px], ...]`; a caption whose start frame is in `[start, end)` is centred at `y_px`), `fixed_y` (px at 1920 height, scaled to the output height; centre y of every caption no `y_overrides` entry or placement override matches; absent = the slot y), `max_bottom_y` (px at 1920 height, scaled to the output height; lowest allowed caption box bottom, gate Z01; default profile: none).
- Caption box: centre y +/- 0.75 x font size, the caption width wide; it contains the rendered ink (glyphs, descenders, soft shadow) and is the box R62, R63, Z01 and automatic placement use.
- Caption timing always comes from the voiceover word timestamps (pinned words); no profile sets a caption rhythm. `build_report.json` -> `captions` reports `events`, `per_10s` and `mean_s` (information only, no gate).
- Automatic placement (R63): per segment, the caption centre moves in 10 px steps to the nearest y inside the safe area (bottom capped at `max_bottom_y` when set) that keeps `clearance` from every HyperFrames DOM element (pins, labels, cards) and every declared native overlay, and does not intersect the projected camera `focus_box`. No free y = fail.

## Build pipeline

1. Captions: pinned timeline words; else BLAKE3-cached faster-whisper words (`small`, int8, beam 5, temperature 0, VAD) + `caption_fixes`, pinned into `master_timeline.json` (fresh copy of the file, so in-memory gate fixes are not written).
2. Pre-flight (layers 1-3, caption placement, profile style gates).
3. Sounds (profile `[sound]`), after pre-flight, before the mix plan and the segment render: `sound.request.ensure_sounds` requests missing files (bundle `out/sound_request/`, exit 3; `--resume` imports the answer); after the plan the Epidemic Sound credit lines of the mixed files are appended to `credits.txt` (docs/SOUND.md).
4. Build manifest `out/build_manifest.json` written (see Build manifest). Segments in parallel within the worker budget (see Resources): native pool `native_workers` x 2 x264 threads; HyperFrames segments in a pool of `hf_parallel` (see Resources; output order is segment order), `hf_workers` capture workers each (`VIDEO_ENGINE_HF_WORKERS` overrides), capture profile `-q draft --crf 14` (JPEG q80 screenshots, x264 ultrafast intermediate; `HF_QUALITY`/`HF_CRF` are part of the segment cache key); loudnorm pass 1 runs concurrently. Every segment is checked for its exact frame count. Results cached by a BLAKE3 hash of sources + config.
5. `.ass` with placement overrides.
6. Three cached passes:
   - composite (cache kind `composite`): segment join (Stream-copy and concat rules) + transition clips + caption burn + profile watermark overlay (PNG drawn with Pillow), exact frame count, no audio, `mux_threads` x264 threads;
   - master audio (cache kind `audio`, AAC m4a): mix (ducking, loudnorm pass 2) and the A01 corrective gain passes, on the audio file alone. The mix is cut to exactly duration x 48000 samples after ducking and before loudnorm, and again after it, so every render of the same inputs has identical PCM. With a profile `[sound]` the mix is voiceover + music (gain, fades, keyframed duck under speech) + each SFX cue (trimmed to `max_s`, at its `gain_db`, delayed to `time_s`) summed without normalisation before the same loudnorm and limiter, so the final file meets the profile loudness target;
   - mux: stream copy of the composite video and the master audio (no re-encode).
   Each cache key is the ffmpeg command with every input path replaced by its sha256 (`manifest.cmd_key`): an audio-only change re-runs only the audio pass and the mux; a visual or caption change re-runs the composite and the mux. Transition clips are redrawn from both neighbouring segments on every build and written bit-exact, so the composite key follows both neighbours. Every stage key also holds the engine source that shapes its product (docs/RUST.md, Cache-key rules).
7. Post-render pixel QA, A01 loudness gate, profile S01 silence gate, profile A02 audio source gate, all on the staged file. The mux writes into a unique staging dir `out/.final.staging-*/` on the output's filesystem; it is removed on every exit path.
8. Publish, only when no stage raised and no gate (pre-flight, post-render QA, A01, S01, A02) reported fail: `os.replace` of the staged file onto `out/final.mp4`, then of `build_report.json` (written through a temp file in `out/`); a stale `build_report.failed.json` is removed. Any failure leaves `out/final.mp4` and `out/build_report.json` byte-identical and writes `out/build_report.failed.json`: the full report with `"ok": false`, `"final": null` and `error` after a gate fail, or `ok`, `final`, `error` and `timings` after a stage error. Library API: `build.build()` raises `build.BuildFailed` (an `EngineError` carrying `result` and `report`) on a gate fail, or with `raise_on_fail=False` returns a `BuildResult` with `ok=False`, `final=None`, `failed` (the fail lines) and `report`; stage errors raise their exception.
9. `build_report.json`: `ok`, `build_id` (same as the manifest), `final_sha256`, profile (`name`, `blake3` of the merged profile), segments (mode, cache hit, seconds), preflight findings, fixes, QA, loudness (with `measured_lra`), captions (`events`, `per_10s`, `mean_s`), timings, `resources` (`budget` and per stage `wall_s`, `cpu_s`, `peak_rss_mb` with per-tool peaks), `stage_keys`, `preflight_subtimings` (`layer2_dom`: seconds summed over HyperFrames segments of `build`, `browser_load`, `r63_rects`, `snapshots`, `bg_screenshots`, `glyph_masks`, `r64_numpy`; `probes` and `cache_hits` of the DOM probe cache, cache kind `dom`), `gates` (see Gates), `sound` with a profile `[sound]` (`music` provenance, `music_file`, `ducking`, `sfx` provenance per asset id, `cues`), `cache` (the build's lease session: `leased` file count, `evicted`, `skipped_leased`, `reclaimed_leases`; paths `<cache root>/<path>`), and `sfx_events` when the scenes have sound cues: one `{kind: "counter_tick", frame (absolute), seg, figure}` per frame on which a counter's shown text changes.

### Build manifest

`out/build_manifest.json`, written before any segment renders: `build_id` (random hex, also in `build_report.json`), `timeline` (sha256), `profile` (`name`, `blake3`), `inputs` (every referenced file), `fonts`, `sounds` (music with `brief_key` and provenance, SFX per kind), `toolchain` (ffmpeg version, x264 args, vendor pins, engine version), `seeds`, `resources`, `stage_keys` (composite and audio cache keys). File entries are `{path, sha256}`; `path` is relative to the project, `cache:<rel>` under the cache root, `engine:<rel>` under the engine checkout, else absolute. A later build reuses the locked sound files (sha256 checked) without asking the sound resolver; a locked file that changed or vanished is a stage error naming `--relock`; a lock that does not cover the timeline (new SFX kind, changed music brief) is ignored. The same inputs give the same final file bytes.

### Resources

One budget `workers` (`VIDEO_ENGINE_WORKERS` > profile `[resources] workers` > auto = clamp(min(CPU count, RAM GB // 1.8), 2, 64)) caps all stages: `native_workers = max(1, workers // 4)` (2 x264 threads each), `hf_workers = max(1, workers // 4)`, `mux_threads = clamp(workers - 2, 1, 6)`. `hf_segments` = 2 when `2 x hf_workers x 2 <= workers`, else 1. A build renders `hf_parallel` HyperFrames segments at once: `hf_segments` when `min(native segments, native_workers) x 2 + hf_segments x hf_workers x 2 <= workers`, else 1. On 8 workers: 2 for a timeline without native segments, 1 otherwise. Each stage's wall time, CPU time and peak RSS (engine plus children, with per-tool peaks) go to `build_report.json` -> `resources`.

### Stream-copy and concat rules

- One eligibility function (`video_engine/streams.py`) decides every stream copy and every concat-demuxer join. Files are joinable when they have the same stream kinds in the same order and every compared parameter is equal.
- Video parameters compared: `codec_name`, `codec_tag_string`, `profile`, `level`, `width`, `height`, `pix_fmt`, `sample_aspect_ratio`, `r_frame_rate`, `avg_frame_rate`, `time_base`, `field_order`, `color_range`, `color_space`, `color_transfer`, `color_primaries`, `chroma_location`, `bits_per_raw_sample`, `has_b_frames`, `refs`, `extradata_hash` (MD5 of the SPS/PPS), `rotation`.
- Audio parameters compared: `codec_name`, `codec_tag_string`, `profile`, `sample_rate`, `channels`, `channel_layout`, `sample_fmt`, `bits_per_raw_sample`, `time_base`, `extradata_hash`.
- Engine segment format: the video stream of a 2-frame encode with `config.X264` at the timeline width, height and fps. A native source is stream-copied only when its video stream equals the engine segment format; the copy keeps the source edit list and carries `"copy": "copy-edit-list"` in its segment key.
- Every segment file (native copy, native encode, camera, HyperFrames) is checked after rendering: decoded frame count equal to the segment frame count, `start_time` 0 and duration `frames / fps`, each within half a frame. A native copy that fails the parameter or timing check is re-encoded; HyperFrames output passes through unchanged only when it is H.264 yuv420p at the timeline size with `r_frame_rate` = `avg_frame_rate` = fps and passes the timing check, else it is re-encoded; any other failure is a stage error.
- Final mux: joinable segments are joined with the concat demuxer; other segments are decoded as separate inputs, retimed to `1/fps` with `setpts=N` and joined with the concat filter. `build_report.json` -> `join` holds `method` (`concat demuxer` or `concat filter`) and `differences` (one `<segment file>: v0.<parameter>: a != b` entry per mismatch against the first segment).
- The output of the final mux and of the gain pass is checked for frame count, start and duration; the gain pass also fails when its copied video stream differs from its input in any compared parameter.


## Cache leases

- Every engine command (`cli.main`) and every `build.build()` call runs in one lease session (`video_engine.cache.session()`, re-entrant; the outermost exit releases).
- Inside a session, each cache file the process resolves or writes (words, segments, maps, their temp files, sound files, sidecars and index files, local test tones) is leased by `cache.acquire(path)` before the process checks it exists; the lease holds until the session exits on success, failure, exception or AwaitingAgent.
- Lease file: `<cache root>/.leases/<pid>-<start>.json` = `{"pid", "start", "paths": [paths relative to the cache root]}`; `start` is field 22 of `/proc/<pid>/stat`. Written atomically under a shared `flock` on `<cache root>/.lock`.
- Eviction holds the exclusive lock while it scans and deletes: LRU `cache.prune()` (after every `put_file` and sound `put`), `cache.clear()` (`--no-cache`, `clean --cache`), `engine cache --prune` and `sound.cache.prune()`. Each keeps every leased file and reports it (`skipped_leased`).
- A lease file whose pid is gone or runs a process with another start time is deleted by the next eviction (`reclaimed_leases`); its files become evictable.
- LRU eviction also keeps the entry being stored, so an entry larger than `VIDEO_ENGINE_CACHE_MAX_MB` stays in the cache until a later eviction.
- Outside a session `acquire` does nothing and eviction treats every file as unleased.

## Delivery

`engine deliver P --dry-run` prints:
- Root `NN - YYYY-MM-DD - Topik`, final dir `05 Final`, assets dir `03 Aset`.
- `NN - Topik - final.mp4`: one file when its size is at most 95,000,000 bytes (`deliver.PART_MAX_BYTES`); larger, `.part1` ... `.partN` byte ranges of at most that size each. `NN - JOIN.txt` names exactly those parts in order (cat / copy /b instructions), or says no join is needed for one file.
- `NN - credits.txt` from the project `credits.txt`.
Requires `settings.project_number`, `settings.topic`, `settings.date`. Refuses a final file that is not the output of the last successful build: missing `build_report.json` / `build_manifest.json`, a `build_report.failed.json` next to it, `build_id` mismatch between report and manifest, or a final file whose sha256 differs from `final_sha256`. No upload is implemented.

## AI providers

`engine draft`, `engine director` and `--ai-qa` send provider-neutral requests (prompt text, JSON schema, images, audio/video files) to one provider. Prompts, schemas, normalising, gates and the repair loop are shared; only transport differs.

| Provider | Model | Media |
|---|---|---|
| `gemini` (default) | Gemini lists below | audio and video via the File API (deleted and verified), images inline |
| `agent` | an agent or human editor answering request bundles; reported model = `[agent] model_label` (default `grok-bot`) | files in the bundle; video as sampled JPEG frames, audio as transcript with word frames |
| `[providers.NAME]` in `ai_providers.toml` | OpenAI-compatible chat completions endpoint | images inline (base64); audio / video inline when listed in `capabilities`, else transcript / sampled frames |

Selection: `--provider NAME` > env `VIDEO_ENGINE_AI_PROVIDER` > `default` in `ai_providers.toml` > `gemini`. An unknown name is an error listing the known names. Every result records `provider` and the `model` that answered.

Retry and fallback (every API provider): HTTP 429 / 503 (`RESOURCE_EXHAUSTED` / `UNAVAILABLE`) or invalid JSON -> retry the same model up to 3 times, waiting 2 s, 5 s, 12 s (+ up to 25 % random jitter). Then the next model. Transport drops without an HTTP status (`RemoteProtocolError`, read/connect timeouts, `ConnectionError`) count as 503. HTTP 404 -> next model at once. Any other status (400, 401, 403, ...) -> error, no retry. Every HTTP request has a 300 s timeout. Every result records `model`, `retries`, `fallback`, `tried` (every attempt with its status). A fallback answer prints `warning: FALLBACK: ...` to stderr and stores the same text in the result (`draft_report.json` -> `rounds[].ai`, AI QA -> a `warn` finding).

### Gemini

- Planning model: `gemini-3.8-flash` (required). Fallback list, last resort only: `gemini-3.6-flash`, `gemini-3-flash-preview`, `gemini-2.5-flash`. QA models: `gemini-3.5-flash-lite`, `gemini-3.1-flash-lite`, `gemini-2.5-flash-lite`.
- Config: JSON output with schema, `MEDIA_RESOLUTION_LOW`, `thinking_budget=1024`.
- Uploaded files are deleted after use and the deletion is verified: `files.get` must fail with 404 or 403 (the File API answers 403 for a deleted name) and the name must be absent from `files.list` (`file_deletions[].verified_gone`).

### Agent handoff

The agent provider writes one self-contained request bundle per request and exits with code 3. The agent writes `response.json` into the bundle and reruns the same command with `--resume`.

| Request | Bundle directory |
|---|---|
| draft, round N | `P/ai_request/draft/N/` |
| `preflight` / `build --ai-qa` | `P/ai_request/aiqa/0/` |
| director | `<bundle-root>/director/<src stem>_<start>s/` |

| File | Content |
|---|---|
| `request.md` | Answer instructions, the resume command, then the exact prompt in request order with image references (`![label](images/NN_label.jpg)`); repair rounds include the previous draft and the gate errors |
| `schema.json` | JSON schema the answer must satisfy |
| `images/NN_*.jpg\|png` | Every image in request order: asset thumbnails (draft), sampled proxy frames labelled `t=S s` (director), segment snapshots (AI QA) |
| `contact_sheet.jpg` | All images on one numbered grid (2 or more images) |
| `transcript.json` | Narration words `{word, start_frame, end_frame}` (draft) |
| `inventory.json`, `credits.json` | Asset inventory and numbered credits.txt lines (draft) |
| `gate_errors.txt`, `previous_response.json` | Gate errors and the rejected answer of the previous round (draft rounds >= 1) |
| `response.json` | Written by the agent: one JSON object valid against `schema.json` |

Resume: the command replays every round from its `response.json`. A response that passes the gates finishes the command (exit 0). A draft response that fails the gates produces the next round's bundle with the errors (exit 3), up to `--max-repairs`; after the last round the draft is rejected (exit 1). Invalid JSON, a non-object, or a schema mismatch is an error naming the file and the failing paths (exit 1). A pending bundle without `response.json` on `--resume` is an error (exit 1). A run without `--resume` deletes the earlier bundles of that request first. The draft sends no video proxies to the agent by default (thumbnails carry 3 frames per video).

### Adding a model (OpenAI-compatible)

Add a table to `ai_providers.toml` (or the file in `VIDEO_ENGINE_AI_CONFIG`) and put the key into the named environment variable:

```toml
default = "gemini"            # provider when no --provider flag and no VIDEO_ENGINE_AI_PROVIDER

[agent]
model_label = "grok-bot"

[providers.mymodel]
base_url = "https://api.example.com/v1"      # POST {base_url}/chat/completions
models = ["model-large", "model-medium"]     # primary first, then fallbacks (draft, director)
qa_models = ["model-small"]                  # optional (--ai-qa); default = models
api_key_env = "MYMODEL_API_KEY"              # env var holding the key; the key itself is never in the file
capabilities = ["image"]                     # image | audio | video input
json_mode = "json_schema"                    # json_schema (schema attached) | json_object (schema in the prompt)
timeout_s = 300
```

Use it with `--provider mymodel`, `VIDEO_ENGINE_AI_PROVIDER=mymodel` or `default = "mymodel"`. A missing key variable is an error naming the variable. Request: one user message with `text` and `image_url` (base64 data URL) items, `input_audio` with the `audio` capability, `video_url` with the `video` capability; without a capability, audio becomes its transcript, video becomes sampled JPEG frames, images become a text note. Replies in a ```` ```json ```` fence are accepted.

### Director

- Footage: 360p 5 fps proxy (ffmpeg spawned by Rust `make_proxy`, written to the run's own `director-<pid>-<random>/proxy` scratch dir, deleted after the request) -> provider (Gemini: File API upload; agent and models without video input: 8 sampled frames).
- Output: shots with `start_s`, `end_s`, `description`, `focus_box` (0-1000 grid), `suggested_camera`, `has_watermark_or_text`.

### Director stage (`engine draft`)

Before the timeline request the provider writes 3 storyboard concepts (request `draft/storyboard`, one repair `draft/storyboard1`). A concept is a list of beats (`from_word`, `to_word`, `goal`, `pattern`, `assets`, `on_screen_text`, `camera`, `transition`) with self scores. The engine rejects concepts that use unknown assets or facts absent from the narration, script, asset hints and credits, then scores the rest: fit 0.35, clarity 0.25, asset availability 0.25, render cost 0.15, minus 0.15 for an opener used in the last `avoid_recent` drafts and 0.03 per recently used transition (max 0.15). The best concept goes into the timeline request as `CHOSEN STORYBOARD`; each segment carries its `goal`. Prompt text and patterns: `video_engine/director/guidance.md`, `video_engine/director/patterns.toml` (progressive_reveal, comparison, tracing, meaningful_repetition, emphasis_by_pause, establish, footage_beat). Output: `draft/storyboards.json`, `draft_report.json` -> `storyboard`. No valid concept = warning and the draft continues without one.

Taste store `profiles/taste/<channel>.json`: `rules`, `liked`, `rejected`, `recent` (opener and transitions of accepted drafts), `avoid_recent`. Its text goes into the storyboard prompt.

`--review` (`--review-rounds` 1 or 2): after a draft passes the gates, up to 16 critical times (cuts, beats, text starts) are sampled as 360 px frames and sent with the timeline (request `draft/review<k>`). A `revise` verdict with a blocker or major finding asks for a revised timeline (`draft/revise<k>`); a revision that fails the gates is dropped and the previous version kept. Every version is saved as `draft/timeline.v<N>.json` and `draft/review.v<N>.json`; `draft_report.json` -> `review`, `versions`.

## Draft

- Inputs: narration (`--voiceover`, else `audio_chain.voiceover_path`, else the first audio file named narasi/narration/voice/vo in the project root or `assets/`), script (`--script`, else `script.txt` / `narasi.txt` / `narration.txt`), `credits.txt` in the project root (required), every file under `assets/` with metadata (`assets/manifest.csv`, `<file>.json` sidecars, existing timeline credit), optional 360p 20 s video proxies.
- Profile: `--profile`, else the existing timeline's `profile`, else `default`; written into the draft timeline.
- Pre-model analysis: narration pauses (profile `[draft]` `min_seg_s` / `max_seg_s`; default 1.5 s / 7 s) give the boundary candidates; words come from the pinned captions or a transcription.
- Prompt: engine rules 1-5 with the profile segment length, then the profile `[draft]` `rules`. With `[draft] map_path = true` a map segment may return `map_path` keys `{at_s, x, y, zoom}` (converted to `camera_path`: first key at frame 0, later keys sorted, deduplicated by frame, clamped to the segment and the value ranges; fewer than 2 keys = repair).
- Model output: JSON matching a schema whose `asset` field is an enum of inventory ids and whose credit field is a credits.txt line number. URLs are copied from credits.txt lines; the model cannot write a URL.
- Each segment carries `narration` (the words it covers) and `why` (how the visual matches those words).
- Request media: narration audio and up to `--video-proxies` video proxies (default 2; agent 0); images and 3 frames per video as 384 px JPEG thumbnails. Gemini uploads audio and proxies via the File API and deletes and verifies them after the last round.
- Pipeline: model -> normalise (frame snapping, contiguity, overlay slots) -> validate -> pre-flight -> on failure send the gate errors back as `GATE ERRORS` and ask for a corrected draft, at most `--max-repairs` rounds (default 2).
- `draft_report.json`: `provider`, `model`, `fallback`, `warnings`, `retries_total`, `repair_rounds`, `rounds[]` (errors per round), `file_deletions[]`, `segments[]` (`narration`, `why`), `normaliser_fixes`, `seconds`. On an exception it holds `error` and the CLI exits 1; while an agent response is pending it holds `awaiting` (bundle path) and the CLI exits 3.

## Limits and not implemented

- Drive delivery: dry-run plan only.
- AI QA: covered by mock tests; not part of the default build.
- OpenAI-compatible providers: covered by mock tests; no endpoint is registered in `ai_providers.toml`.
- faster-whisper word output can differ between processes for the same audio (CTranslate2 int8 CPU). Pinned `captions` remove this from builds; `engine words --retranscribe` can produce different words, and `caption_fixes` must then cover the new variants.
